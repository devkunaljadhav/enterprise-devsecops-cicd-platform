1. OVERVIEW
-----------

This runbook describes how to build, scan, containerize, deploy, and monitor
a Netflix-style application using Jenkins, SonarQube, Trivy, Docker, AWS EKS,
Terraform, Prometheus, and Grafana.

Delivery flow:

Developer -> GitHub -> Jenkins
                         |
                         +-> SonarQube analysis and quality gate
                         +-> Trivy filesystem and image scans
                         +-> Docker image build and push
                         +-> Docker container deployment
                         +-> AWS EKS Kubernetes deployment
                         +-> Prometheus and Grafana monitoring
                         +-> Email build notifications


2. SECURITY BEFORE STARTING
---------------------------

This is an infrastructure and learning environment. Do not use administrator
IAM permissions or embed real credentials in Jenkinsfiles or Git repositories.

Replace every placeholder such as <DOCKER-USERNAME>, <REGION>, <CLUSTER-NAME>,
<TMDB-API-KEY>, and <JENKINS-URL> before running the commands.

Store these values in Jenkins Credentials:

- Docker Hub username and password or access token
- SonarQube secret token
- SMTP username and app password
- TMDB API key
- AWS credentials or an instance IAM role
- Kubernetes kubeconfig file

Rotate any credential that has already been committed to a repository or
shared in a log. SonarQube, Jenkins, Grafana, Prometheus, and AWS security
groups should not be publicly accessible unless explicitly protected.

4. INSTALL TERRAFORM, KUBECTL, AND AWS CLI
------------------------------------------

Run on the Jenkins EC2 instance:

    sudo apt update
    sudo apt install -y curl wget unzip gnupg apt-transport-https

    # Terraform
    wget -O- https://apt.releases.hashicorp.com/gpg |
      sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg

    echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] \
      https://apt.releases.hashicorp.com $(lsb_release -cs) main" |
      sudo tee /etc/apt/sources.list.d/hashicorp.list

    sudo apt update
    sudo apt install -y terraform

    # kubectl
    curl -LO "https://dl.k8s.io/release/$(curl -Ls \
      https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
    sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
    kubectl version --client

    # AWS CLI
    curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" \
      -o "awscliv2.zip"
    unzip awscliv2.zip
    sudo ./aws/install
    aws --version


5. INSTALL JAVA, JENKINS, AND DOCKER
------------------------------------

Run on the Jenkins EC2 instance:

    sudo apt update
    sudo apt install -y openjdk-21-jdk curl ca-certificates gnupg

Jenkins WAR installation:

    sudo mkdir -p /opt/jenkins
    cd /opt/jenkins
    sudo wget https://get.jenkins.io/war-stable/latest/jenkins.war
    sudo chmod 755 jenkins.war
    nohup java -Djava.net.preferIPv4Stack=true \
      -jar /opt/jenkins/jenkins.war \
      >/opt/jenkins/jenkins.log 2>&1 &

Open:

    http://<JENKINS-HOST>:8080

Complete the Jenkins setup wizard and retrieve the initial administrator
password from:

    sudo cat /opt/jenkins/secrets/initialAdminPassword

Docker installation:

    sudo install -m 0755 -d /etc/apt/keyrings
    curl -fsSL https://download.docker.com/linux/ubuntu/gpg |
      sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
    sudo chmod a+r /etc/apt/keyrings/docker.gpg

    echo "deb [arch=$(dpkg --print-architecture) \
      signed-by=/etc/apt/keyrings/docker.gpg] \
      https://download.docker.com/linux/ubuntu \
      $(. /etc/os-release && echo "$VERSION_CODENAME") stable" |
      sudo tee /etc/apt/sources.list.d/docker.list >/dev/null

    sudo apt update
    sudo apt install -y docker-ce docker-ce-cli containerd.io \
      docker-buildx-plugin docker-compose-plugin
    sudo usermod -aG docker ubuntu
    sudo systemctl enable docker
    sudo systemctl restart docker

Log out and back in, or start a new login shell, before running Docker
commands. Do not make the Docker socket world-writable.

7. RUN SONARQUBE
----------------

Start SonarQube:

    docker run -d --name sonar \
      --restart unless-stopped \
      -p 9000:9000 \
      sonarqube:lts-community

Open:

    http://<JENKINS-HOST>:9000

Change the initial administrator password immediately.

Create a SonarQube project and token:

1. Open Administration -> Security -> Users.
2. Generate a token for the Jenkins service account.
3. Save the token in Jenkins as a Secret Text credential.
4. In Jenkins, open Manage Jenkins -> System -> SonarQube servers.
5. Add the SonarQube server name and URL.
6. Configure the Jenkins server URL in the SonarQube webhook:

       http://<JENKINS-HOST>:8080/sonarqube-webhook/

Recommended quality gate configuration:

- Quality gate must pass for new bugs and vulnerabilities.
- Quality gate must pass for code-smell and coverage targets required by policy.


8. TMDB APPLICATION API KEY
---------------------------

1. Create or sign in to a TMDB developer account.
2. Generate an API key for the application.
3. Store the key in Jenkins as a Secret Text credential.
4. Pass it to Docker using a Jenkins credential binding or build argument.

Example Jenkins environment binding:

    environment {
        TMDB_V3_API_KEY = credentials('tmdb-api-key')
    }

Example Docker build command:

    docker build \
      --build-arg TMDB_V3_API_KEY="$TMDB_V3_API_KEY" \
      -t <DOCKER-USERNAME>/netflix:latest .

Do not commit the API key to source control or hard-code it in a Dockerfile.

10. TERRAFORM EKS PROVISIONING
------------------------------

Create a private S3 bucket for the Terraform state:

    devsecops-netflix-<unique-suffix>

Enable:

- Default encryption
- Bucket versioning
- Public access blocking
- S3 state lifecycle controls
- DynamoDB state locking if Terraform configuration requires it

Configure Terraform with a backend or variables appropriate for this
repository. Verify that the EKS Terraform directory contains the provider,
cluster, node group, networking, IAM, and backend configuration.

Create a Jenkins pipeline job named EKS-Provision:

    pipeline {
        agent any

        parameters {
            choice(name: 'ACTION', choices: ['apply', 'destroy'], description: 'Infrastructure action')
        }

        stages {
            stage('Checkout') {
                steps {
                    git branch: 'main',
                        url: 'https://github.com/devkunaljadhav/enterprise-devsecops-cicd-platform.git'
                }
            }

            stage('Terraform Version') {
                steps {
                    sh 'terraform --version'
                }
            }

            stage('Terraform Init') {
                steps {
                    dir('EKS_TERRAFORM') {
                        sh 'terraform init'
                    }
                }
            }

            stage('Terraform Validate') {
                steps {
                    dir('EKS_TERRAFORM') {
                        sh 'terraform validate'
                    }
                }
            }

            stage('Terraform Plan') {
                steps {
                    dir('EKS_TERRAFORM') {
                        sh 'terraform plan -out=tfplan'
                    }
                }
            }

            stage('Apply or Destroy') {
                steps {
                    dir('EKS_TERRAFORM') {
                        sh "terraform ${params.ACTION} --auto-approve tfplan"
                    }
                }
            }
        }
    }

Important: Terraform's apply/destroy syntax with a saved plan is environment-
dependent. For a destroy plan, generate a destroy plan separately. The safer
production pattern is:

    terraform apply -auto-approve tfplan
    terraform destroy -auto-approve

Run apply first. Verify the cluster:

    aws eks list-clusters --region <REGION>
    aws eks update-kubeconfig \
      --region <REGION> \
      --name <CLUSTER-NAME>
    kubectl get nodes
    kubectl get namespaces

Never run destroy without exporting logs, reviewing dependencies, and
confirming that the environment is disposable.


11. INSTALL PROMETHEUS AND NODE EXPORTER
-----------------------------------------

Create a dedicated monitoring server and launch Ubuntu 24.04 LTS.

Install Prometheus:

    sudo useradd --system --no-create-home --shell /bin/false prometheus
    wget https://github.com/prometheus/prometheus/releases/download/v2.47.1/\
prometheus-2.47.1.linux-amd64.tar.gz
    tar -xvf prometheus-2.47.1.linux-amd64.tar.gz
    cd prometheus-2.47.1.linux-amd64

    sudo mv prometheus promtool /usr/local/bin/
    sudo mv consoles console_libraries /etc/prometheus/
    sudo mv prometheus.yml /etc/prometheus/prometheus.yml
    sudo mkdir -p /data
    sudo chown -R prometheus:prometheus /etc/prometheus /data

Create /etc/systemd/system/prometheus.service:

    [Unit]
    Description=Prometheus
    Wants=network-online.target
    After=network-online.target

    [Service]
    User=prometheus
    Group=prometheus
    Type=simple
    Restart=on-failure
    ExecStart=/usr/local/bin/prometheus \
      --config.file=/etc/prometheus/prometheus.yml \
      --storage.tsdb.path=/data \
      --web.listen-address=0.0.0.0:9090 \
      --web.enable-lifecycle

    [Install]
    WantedBy=multi-user.target

Start and verify Prometheus:

    sudo systemctl daemon-reload
    sudo systemctl enable --now prometheus
    sudo systemctl status prometheus
    promtool check config /etc/prometheus/prometheus.yml

Open:

    http://<MONITORING-HOST>:9090
    http://<MONITORING-HOST>:9090/targets

Install Node Exporter:

    sudo useradd --system --no-create-home --shell /bin/false node_exporter
    wget https://github.com/prometheus/node_exporter/releases/download/v1.6.1/\
node_exporter-1.6.1.linux-amd64.tar.gz
    tar -xvf node_exporter-1.6.1.linux-amd64.tar.gz
    sudo mv node_exporter-1.6.1.linux-amd64/node_exporter /usr/local/bin/

Create /etc/systemd/system/node_exporter.service:

    [Unit]
    Description=Node Exporter
    Wants=network-online.target
    After=network-online.target

    [Service]
    User=node_exporter
    Group=node_exporter
    ExecStart=/usr/local/bin/node_exporter \
      --collector.logind
    Restart=on-failure

    [Install]
    WantedBy=multi-user.target

Start Node Exporter:

    sudo systemctl daemon-reload
    sudo systemctl enable --now node_exporter
    sudo systemctl status node_exporter

Add these targets to /etc/prometheus/prometheus.yml:

    scrape_configs:
      - job_name: 'node-exporter'
        static_configs:
          - targets:
              - '<JENKINS-HOST>:9100'
              - '<MONITORING-HOST>:9100'

      - job_name: 'jenkins'
        metrics_path: '/prometheus'
        static_configs:
          - targets:
              - '<JENKINS-HOST>:8080'

Reload Prometheus:

    promtool check config /etc/prometheus/prometheus.yml
    curl -X POST http://localhost:9090/-/reload

14. APPLICATION CI/CD JENKINS PIPELINE
--------------------------------------

Create a pipeline job that checks out the application repository and uses these
stages:

1. Clean workspace
2. Checkout source
3. SonarQube analysis
4. SonarQube quality gate
5. Install dependencies
6. Trivy filesystem scan
7. Docker build and push
8. Trivy image scan
9. Docker deployment
10. Kubernetes deployment
11. Email notification

Example pipeline:

    pipeline {
        agent any

        tools {
            jdk 'jdk21'
            nodejs 'node25'
        }

        environment {
            SCANNER_HOME = tool 'sonar-scanner'
            DOCKER_IMAGE = '<DOCKER-USERNAME>/netflix'
        }

        stages {
            stage('Clean Workspace') {
                steps {
                    cleanWs()
                }
            }

            stage('Checkout') {
                steps {
                    git branch: 'main',
                        url: 'https://github.com/<YOUR-GITHUB-USER>/<YOUR-APP-REPOSITORY>.git'
                }
            }

            stage('SonarQube Analysis') {
                steps {
                    withSonarQubeEnv('sonar-server') {
                        sh '''
                            $SCANNER_HOME/bin/sonar-scanner \
                              -Dsonar.projectName=netflix \
                              -Dsonar.projectKey=netflix
                        '''
                    }
                }
            }

            stage('Quality Gate') {
                steps {
                    waitForQualityGate(
                        abortPipeline: true,
                        credentialsId: 'sonar-token'
                    )
                }
            }

            stage('Install Dependencies') {
                steps {
                    sh 'npm ci'
                }
            }

            stage('Trivy Filesystem Scan') {
                steps {
                    sh 'trivy fs --severity HIGH,CRITICAL --exit-code 0 . > trivyfs.txt'
                    archiveArtifacts artifacts: 'trivyfs.txt', fingerprint: true
                }
            }

            stage('Docker Build and Push') {
                steps {
                    withCredentials([
                        string(credentialsId: 'tmdb-api-key', variable: 'TMDB_V3_API_KEY')
                    ]) {
                        withDockerRegistry(
                            credentialsId: 'docker-hub',
                            toolName: 'docker'
                        ) {
                            sh '''
                                docker build \
                                  --build-arg TMDB_V3_API_KEY="$TMDB_V3_API_KEY" \
                                  -t $DOCKER_IMAGE:$BUILD_NUMBER .
                                docker push $DOCKER_IMAGE:$BUILD_NUMBER
                            '''
                        }
                    }
                }
            }

            stage('Trivy Image Scan') {
                steps {
                    sh 'trivy image --severity HIGH,CRITICAL --exit-code 0 \
                        $DOCKER_IMAGE:$BUILD_NUMBER > trivyimage.txt'
                    archiveArtifacts artifacts: 'trivyimage.txt', fingerprint: true
                }
            }

            stage('Deploy to Docker') {
                steps {
                    sh '''
                        docker rm -f netflix || true
                        docker run -d --name netflix \
                          -p 8081:80 \
                          $DOCKER_IMAGE:$BUILD_NUMBER
                    '''
                }
            }

            stage('Deploy to EKS') {
                steps {
                    dir('Kubernetes') {
                        withKubeConfig(
                            credentialsId: 'k8s',
                            contextName: ''
                        ) {
                            sh 'kubectl apply -f deployment.yml'
                            sh 'kubectl apply -f service.yml'
                            sh 'kubectl rollout status deployment/netflix-app --timeout=5m'
                            sh 'kubectl get pods,svc'
                        }
                    }
                }
            }
        }

        post {
            always {
                emailext(
                    to: '<NOTIFICATION-EMAIL>',
                    subject: "Jenkins: ${currentBuild.fullDisplayName} - ${currentBuild.currentResult}",
                    body: "Build: ${env.BUILD_URL}",
                    attachLog: true,
                    attachmentsPattern: 'trivyfs.txt,trivyimage.txt'
                )
            }
        }
    }


15. DOCKER TROUBLESHOOTING
--------------------------

If Jenkins cannot access Docker:

    sudo systemctl daemon-reload
    sudo systemctl restart docker
    sudo usermod -aG docker jenkins
    sudo systemctl restart jenkins

Verify:

    docker ps

Do not use:

    sudo chmod 777 /var/run/docker.sock

It grants unrestricted access to the Docker daemon and effectively grants
host-level privileges. Use Jenkins and Docker group permissions instead.

If Docker reports an API version mismatch, verify the Docker Engine and Jenkins
Docker plugin versions, then remove temporary API overrides after confirming
the compatibility fix.


16. KUBERNETES TROUBLESHOOTING
------------------------------

Recreate the Jenkins kubeconfig:

    aws eks update-kubeconfig \
      --region <REGION> \
      --name <CLUSTER-NAME>

Copy ~/.kube/config to Jenkins as the k8s Secret File credential. The Jenkins
service identity must have permission to access the EKS cluster.

Verification commands:

    kubectl get nodes
    kubectl get pods -A
    kubectl get deployments -A
    kubectl get svc -A
    kubectl describe pod <POD-NAME>
    kubectl logs <POD-NAME>

Remove a stopped Docker container:

    docker ps -a
    docker stop <CONTAINER-ID>
    docker rm <CONTAINER-ID>

To inspect or expose a LoadBalancer service:

    kubectl get svc netflix-app
    kubectl describe svc netflix-app

Do not patch a service with a hard-coded public IP unless that IP is allocated
to the AWS account and managed for the target load balancer.

18. CLEANUP
-----------

Before deleting resources:

1. Export Jenkins logs, SonarQube results, and Trivy reports.
2. Back up the Terraform state and release notes.
3. Verify that no team member or other environment depends on the cluster.
4. Remove application resources from EKS.
5. Run the Terraform destroy pipeline or destroy plan.
6. Remove public DNS records and security group rules.
7. Delete monitoring servers and disposable EC2 instances.
8. Rotate credentials used during the deployment.

Recommended Kubernetes cleanup:

    kubectl delete -f Kubernetes/service.yml
    kubectl delete -f Kubernetes/deployment.yml

Recommended Terraform cleanup:

    cd EKS_TERRAFORM
    terraform destroy -auto-approve
